A production web console for a stone-fabrication business, built end-to-end:
FastAPI + PostgreSQL backend, React/TypeScript PWA frontend, deployed to Azure
App Service via GitHub Actions. It runs the company's daily payment intake,
delivery tracking, and slab-yard scanning workflows, and talks to AI-agent
workflows (n8n + Claude) that do the heavy lifting.

> **What was scrubbed:** coworker names/emails in seed data and docs are
> fictional placeholders, and internal URLs/IDs are redacted. No secrets were
> ever committed in either repo — all credentials live in `.env` (gitignored)
> and GitHub Actions secrets. See `EMG_CONSOLE_PROJECT_SUMMARY.md` for the
> full architecture write-up.

## What it does

- **Payments board** — mirrors the company's Airtable payment log into
  Postgres (idempotent sync, write-through edits with least-privilege
  read/write tokens), with role-based views for owner, managers, and yard.
- **Check capture → AI decision flow** — phone camera capture of paper
  checks; an n8n workflow OCRs the check, matches it to a job in QuickBooks /
  Moraware, and when it can't decide, posts a **question card** back to the
  console. A human taps an answer, the workflow resumes. Web Push
  notifications (VAPID) land the question on the right person's lock screen.
- **Slab label scanning** — yard crew scans QR labels on stone slabs; scans
  become job-form notes in Moraware. Photos whose QR fails are read by a
  **Claude vision fallback** that extracts the printed ID.
- **Materials catalog** — nightly GitHub Actions job refreshes the materials
  list, with **Claude-powered extraction** normalizing supplier data.
- **Auth** — Google Sign-In verified server-side, signed httpOnly session
  cookies, a seeded role roster (admin / manager / yard), full audit log.

## Architecture

```
React PWA (Vite, Tailwind, service worker, Web Push)
        │ session cookie (Google Sign-In → itsdangerous)
FastAPI backend ── SQLAlchemy/Alembic ── PostgreSQL
        │ X-Pilot-Secret webhooks (both directions)
n8n agent workflows ── QuickBooks · Moraware · Google Drive · Claude API
        │
Airtable (mirrored read-only + write-through edits)
```

Deployed as a single Azure Web App (multi-stage Docker build); CI runs the
test suite, builds the frontend, and deploys on push to `main`.

## Highlights worth reading

- `backend/app/routers/hooks.py` — the n8n ⇄ console webhook contract:
  create/update/question/final/find, with resume-URL round-trips so a paused
  agent workflow can continue after a human answers.
- `backend/app/notify.py` — Web Push fan-out with per-role targeting.
- `n8n/build_pilot_workflow.py` — the n8n workflows are **generated by
  script** (not hand-exported), so they stay reviewable, diffable, and
  secret-free.
- `backend/app/tests/` — 11 test modules covering auth, role gating, sync
  idempotency, webhook auth failures, and the decision-resume race.
- `STAGE*_BUILD_PLAN.md` / `PROJECT_STATE.md` — the staged build plans and
  as-built state docs the project was developed against.

## Run locally

```
cp .env.example .env      # fill in what you have; app degrades gracefully
docker compose up --build
```

- Frontend: https://localhost:5173 (self-signed cert for dev — required for
  the camera; accept the browser warning once)
- API: http://localhost:8000/api/health

Tests: `docker compose exec backend pytest`
